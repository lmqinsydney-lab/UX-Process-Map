# 可视化体验链路（UX Journey Canvas）· Demo 设计文档

日期：2026-07-30
状态：已确认（本文档为 Demo 版本设计基线）

## 1. 背景与定位

交互体验设计师目前以「页面为节点的流程图」形式交付设计稿（Figma 大图）：页面按流程节点分组、从左到右线性排布，页面上方标注页面名+状态，页面间有流转关系，还包含分支、异常、反向流程。

本项目将这种交付物升级为一个可交互的 Web 工具——「可视化体验链路」：无限画布上的流程全览 + 可点击下钻的页面/模块详情。

- 终态愿景：设计师可在画布上直接编辑流程（编辑器），并接入 AI 能力（对话编辑、生图等）。
- 本次范围（Demo）：只读演示版，用真实项目（月付分期还款流程）数据，向团队演示产品形态。编辑与 AI 均为 UI 占位或不做。

## 2. 术语与信息架构

四层结构，自上而下：

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| 流程节点 ProcessNode | 页面的分组容器，代表流程阶段，可带节点级说明 | 「入口-增加按钮气泡引导」「还款流程」 |
| 页面 Page | 流程中的一个页面，属于唯一流程节点 | 「还款页」「分期计划半层」 |
| 状态 State | 页面维度的状态枚举，每个状态一张截图 | 还款页的「不展开期数/展开期数/未配置优惠」 |
| 模块 Module | 页面内的功能区块，有自己的说明与状态枚举；可被多页面复用 | 「分期优惠」「期数选择」 |
| 连线 Edge | 页面（可精确到状态）之间的流转关系 | 本月账单 →（点击分期还款）→ 还款页 |

注：早期讨论中的「模版」概念已废弃，只保留「模块」。

## 3. 数据模型

单份 JSON 配置驱动整个 Demo（未来编辑器读写的就是这份数据）。

```jsonc
{
  "project": { "name": "月付-分期还款", "version": "demo-1" },
  "processNodes": [
    { "id": "entry", "name": "入口-增加按钮气泡引导", "note": "三个入口页均增加按钮气泡引导" }
  ],
  "modules": [
    {
      "id": "installment-coupon",
      "name": "分期优惠",
      "desc": "优惠文案展示规则：默认选中优惠力度最大的期数……",
      "states": [
        { "id": "has-coupon", "name": "有优惠", "note": "……" },
        { "id": "no-coupon", "name": "无优惠", "note": "……" }
      ]
    }
  ],
  "pages": [
    {
      "id": "repay-page",
      "processNodeId": "repay-flow",
      "name": "还款页",
      "desc": "承接三个入口的分期还款动线……",
      "onlineRefs": [ { "name": "线上版本截图", "url": "…" } ],
      "states": [
        { "id": "collapsed", "name": "不展开期数", "image": "assets/pages/repay-page/collapsed.png", "note": "…" }
      ],
      "moduleInstances": [
        {
          "moduleId": "installment-coupon",
          "instanceNote": "本页命中优惠时优先展示优惠文案",
          "hotzones": { "collapsed": { "x": 6, "y": 22, "w": 88, "h": 12 } }
        }
      ]
    }
  ],
  "edges": [
    {
      "id": "e1",
      "from": { "pageId": "bill-month" },
      "to": { "pageId": "repay-page", "stateId": "collapsed" },
      "event": "点击分期还款按钮",
      "condition": "存在可分期账单",
      "type": "main"   // main 主流程 | branch 分支 | error 异常 | back 反向
    }
  ]
}
```

要点：

- 模块全局定义（`modules`），页面通过 `moduleInstances` 引用并附实例说明与热区，天然支撑「出现在哪些页面」的反查。
- 热区坐标为相对截图的百分比（x/y/w/h），按「页面状态 id」分别标注——不同状态下模块位置可不同；某状态无该模块则不配热区。
- 状态间流转也用 `edges` 表达（from/to 同页不同状态），全览展开状态时渲染。

## 4. 画布全览

技术：React + Vite + React Flow（xyflow）。平移缩放、小地图、缩放控件开箱即用；视觉风格借鉴 basketikun/infinite-canvas（顶栏 + 浅色画布），不引用其代码（AGPL-3.0，且剥离成本高）。

- 流程节点 = 分组容器节点：浅色圆角底板 + 标题栏（名称 + 节点级说明入口），内部横排页面卡片；容器按主流程从左到右排布。布局坐标预先写在数据里（Demo 不做自动布局）。
- 页面卡片：默认状态截图缩略 + 页面名 + 状态数角标。
  - 点击卡片本体 → 进入聚焦态。
  - 点击状态角标 → 卡片原位展开为一排状态子卡片（含各状态缩略图），并显示状态间流转线；再点收起（方案 C，讨论确认）。
- 连线：
  - 类型视觉区分：主流程实线加粗；分支实线细；异常红色虚线；反向灰色虚线回勾。
  - 线上常显简短事件标签（如「点击分期还款」）。
  - 点击连线 → 弹出气泡：完整触发事件、判断条件、类型、去向；点击空白关闭。

## 5. 聚焦态（核心画面）

入口：点击页面卡片，画布平滑缩放推近该节点后切入聚焦布局。

布局（已出布局稿确认）：

- 顶栏：「返回全览」、面包屑（流程节点 › 页面）、缩放比例。
- 左侧：当前状态截图居中展示。
  - 模块热区默认虚线描边提示可点；hover 加深。
  - 选中模块后：整页覆盖黑色半透明蒙层，仅选中模块区域镂空亮出（聚光灯效果，用户确认）。
- 右侧面板 · 页面详情（默认视图）：
  - 状态 tab：切换时左侧截图与热区同步切换。
  - 模块构成列表：与左侧热区双向联动（点热区=点列表行），点击进入模块详情。
  - 页面说明（自由文本，对应交付图中的页面标注）。
  - 线上已有页面（外链/截图）。
  - 编辑按钮 → 对话输入框（纯 UI 占位，可输入不生效）。
- 右侧面板 · 模块详情：
  - 模块状态枚举 tab（Demo 阶段切换仅更新说明文字，不要求截图联动）。
  - 模块说明（通用说明 + 本页实例说明）。
  - 「出现在哪些页面」：模块复用索引，点击跨页跳转到对应页面的聚焦态。
  - 编辑按钮（同上占位）、「返回页面详情」。
- 翻页：聚焦态左右两侧「上一页 / 下一页」箭头，沿主流程顺序切换页面，无需退回全览。

## 6. 素材管线（两步走，用户确认）

1. 第一步：用户将图二原始大图放入 `assets/source/`，脚本程序化裁切各「页面×状态」，输出 `assets/pages/<pageId>/<stateId>.png`（低清占位）。
2. 第二步：提供 Figma 导出命名清单（即上述同名路径规则），用户导出高清图按名覆盖即完成替换，代码零改动。
3. 热区坐标由开发侧对照截图人工标注进 JSON，用户无需操心。

## 7. Demo 数据范围

图二完整流程：约 5 个流程节点（入口-增加按钮气泡引导 / 还款流程 / 分期还款页 / 分期结果页 / 分期记录·详情页）、约 13 个页面及其状态。页面说明、模块说明、连线事件/条件优先采用图二标注原文，缺失处以合理占位文案补齐并标记待补。

## 8. 技术结构（Demo）

- React 18 + Vite + TypeScript + @xyflow/react。
- 关键组件：`CanvasOverview`（全览）、`ProcessGroupNode`、`PageCardNode`、`StateSubNode`、`FlowEdge`（含标签与点击气泡）、`FocusView`（聚焦态壳）、`PageViewer`（左侧截图+热区+聚光灯蒙层）、`DetailPanel`（页面详情/模块详情两视图）、`ChatEditStub`（对话编辑占位）。
- 数据：`src/data/project.json` + TypeScript 类型定义。
- 部署：静态构建产物，可本地打开或任意静态托管。

## 9. 非目标（本次不做）

编辑落库与撤销重做、真实 AI 对话与生图、拖拽创建节点/连线、自动布局、多人协作、移动端适配、超大规模性能优化。

## 10. 决策记录

| 决策点 | 结论 |
| --- | --- |
| 工具定位 | 终态编辑器；本次只做只读 Demo |
| 全览组织方式 | 方案 C：页面聚合 + 状态角标原位展开 |
| 模块 vs 模版 | 无模版概念，只有模块（全局定义+页面实例引用） |
| 页面素材 | 真实截图 + 热区；两步走（先裁图二，后换 Figma 高清图） |
| 模块选中态 | 黑色半透明蒙层 + 选中模块镂空（聚光灯） |
| 面板编辑能力 | 页面/模块详情均有编辑按钮，对话编辑为纯 UI 占位 |
| 技术路线 | React + React Flow；不基于 infinite-canvas 改造（AGPL + 剥离成本） |
